# 架构与技术取舍

## 从问题出发

1. 中文问题与俄文术语存在词面差异，书名与人名还有异译。
2. 检索模型有固定窗口，字符数不能直接替代token数。
3. 资料会更新，来源卡片需要绑定具体文档版本。
4. 用户停止等待时，需要释放真实的推理任务与连接。

## 存储职责

SQLite保存文档、活动版本、页快照、原始位置与FTS索引。导入按内容和解析指纹幂等，替换在事务中切换活动版本。删除后新检索排除文档，旧片段接口返回410。

Qdrant local保存派生向量。collection名称包含语料和编码器指纹，建库完成并核对points后才激活。查询时检查模型/语料版本，再从活动SQLite记录取回原文。两个存储通过指纹与活动指针协调。

## 分块和复用

分页后先做带重叠的字符分块，能放入E5窗口的旧片段保留。超窗片段继续切分，每段使用实际tokenizer对“passage前缀 + 标题 + 正文 + 特殊token”精确计数。Unicode原始偏移始终指向未规范化的页快照。

模型输入单独进行NFC、软连字符处理与空白折叠。缓存键由完整编码器指纹和规范化输入哈希组成，读取时检查维度、有限值和单位范数。原来被截断的向量不能作为完整新片段的编码复用。

## 检索模式

- `bm25`保留关键词和精确专名匹配。
- `dense`使用384维multilingual-e5-small向量与cosine。
- `hybrid`对候选列表做RRF，k为60。
- `hybrid_terms`显式匹配有限中俄术语，构造检索子查询后融合，返回词表指纹与命中项。该模式适用于当前领域术语，完整原问题仍传给生成模型。

候选列表最多提供4段生成证据，每份文档最多2段，完全相同的文本去重。生成预算通过模型自己的聊天模板和分词端点计数，预留输出与64 token余量，超预算时移除排序最低的来源。

## 生成与引用

`LocalLlamaBackend`接受字面回环HTTP地址，先核对服务端模型别名和上下文，再发送问题与证据。JSON Schema把有依据回答和资料不足分成两个分支。正文引用集合必须与实际提供的source_id及引用列表一致。

引用校验提供可定位性。答案每项主张是否得到来源支持，仍需另外评测。语料中的模型控制标记在生成上下文中转义，原文快照保留原始字符。

## 流式与取消

应用使用固定两步流程，检索后生成。模型返回结构化JSON流，服务从未完成JSON中提取稳定的answer字符串前缀，处理转义、UTF-8分包和Unicode代理项。只有正文进入浏览器，最终完整结果仍执行原有校验。

客户端通过fetch读取SSE，检查请求ID和序号。预览到done前标为待校验，error或连接提前结束时清除预览。队列上限16条，单次回答有总时限。客户端断开后取消生产任务，屏蔽取消的清理区确保上游HTTP流完成关闭。该清理行为通过真实模型slots空闲检查验证。

## 本地模式的边界

Qdrant local由一个进程独占，建库CLI和API需要分时运行。当前SQLite文档导入同步执行。原型面向本机使用，部署时绑定127.0.0.1。持久化任务、多用户权限与服务化索引将在对应需求出现后单独设计和评测。
